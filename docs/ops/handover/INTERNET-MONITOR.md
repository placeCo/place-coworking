## 2. Предлагаемая схема

```
[ESP32 на Wi-Fi 1 этажа]──┐   каждые 2 мин ping
[ESP32 на Wi-Fi 3 этажа]──┼──> Healthchecks.io (free, 20 проверок) ──> статус up/down
[Pi / роутер по кабелю  ]──┘
                                 │  (Apps Script читает API раз в ~5 мин, read-only ключ)
                                 v
                    netmon.gs (в bridge или отдельным проектом)
                     10:00–21:59 → PLACE Team (админы на смене)
                     22:00–09:59 → личка George (только если лежит ≥ 15 мин)
```

- **Почему Healthchecks.io, а не UptimeRobot:** бесплатно 20 проверок, heartbeat точно есть во free, есть API и Telegram/webhook во free. Сервис не зависит от Google и от нашей сети. UptimeRobot Free оставляем для **сайта** (HTTP-монитор placecoworking.com, 5 мин, email на info@). Этого монитора сейчас тоже нет.
- **Почему маршрутизирует наш скрипт, а не встроенный Telegram Healthchecks:** Healthchecks не умеет правило «днём админам, ночью George». Наш `netmon.gs` берёт статусы через API и решает сам.
- **Логика алертов** (`netmon/netmon.gs`):
  - днём сразу в PLACE Team (RU + TH): «нет интернета на X с HH:MM, проверьте роутер/питание»;
  - ночью в личку George, только если сеть лежит ≥ 15 минут (`NIGHT_MIN_DOWN`);
  - если упало днём и не поднялось к 22:00, один раз пишем George; если упало ночью и не поднялось к 10:00, один раз пишем смене;
  - восстановление сообщаем тому, кто сейчас дежурит;
  - если упали **все** сети сразу, добавляем: «вероятно, нет электричества или упал главный роутер/линия».
- **Чем различаем Wi-Fi и провайдера:** на каждой линии провайдера одна проводная проверка, плюс по одной Wi-Fi проверке на этаж. Упала только Wi-Fi проверка этажа → точка доступа или роутер этажа. Упали и проводная, и Wi-Fi → провайдер или питание.
- **Нагрузка:** Healthchecks без лимита на пинги. Apps Script делает 1 запрос к API раз в 5 минут (~290 в день). Это укладывается в квоты, новых прогонов Lead не нужно.

## 3. Какие проверки завести (предложение, итого 4–7 из 20 бесплатных)

| Check (slug) | Где стоит | Что проверяет | Период / grace |
|---|---|---|---|
| `isp-a-wired` | Pi или роутер линии A, по кабелю | линия провайдера A | 2 мин / 5 мин |
| `isp-b-wired` | то же для линии B, если есть | линия провайдера B | 2 / 5 |
| `floor1-wifi` | ESP32 у розетки на 1 этаже | Wi-Fi 1 этажа + выход в интернет | 2 / 5 |
| `floor3-wifi` | ESP32 на 3 этаже | Wi-Fi 3 этажа + интернет | 2 / 5 |
| `floor2-wifi`, `floor5-wifi` | по желанию (офисы) | Wi-Fi офисных этажей | 2 / 5 |
| UptimeRobot HTTP `placecoworking.com` | снаружи | сайт | 5 мин (free) |

При таких настройках алерт приходит в течение ~5–10 минут после падения.

## 4. Что нужно (железо и доступы)

**Железо** (варианты, выбирает George):
1. **ESP32 DevKit** на каждый этаж с Wi-Fi: ~150–250 ฿ за штуку (Shopee/Lazada) + любое USB-зарядное 5V + розетка, где плата будет висеть постоянно. Проверяет именно Wi-Fi этажа. Скетч: `netmon/esp32-heartbeat.ino`.
2. **Проводная проверка линии:**
   - если роутер на **OpenWrt/MikroTik**, железо не нужно, хватает cron/scheduler на роутере (`netmon/heartbeat.sh` или `/tool fetch` в MikroTik);
   - иначе **Raspberry Pi Zero 2 W / Pi 4** (~700–1 500 ฿ + SD-карта + блок питания) по кабелю в роутер. Pi может раз в час ещё делать speedtest.
   - Обычные ISP-роутеры (Huawei/ZTE от 3BB/AIS/True) cron не умеют.
3. Итого на 1 и 3 этаж + одна линия: **~500–2 000 ฿**.

**Доступы и информация:**
- Схема сети: сколько линий провайдера, какие роутеры и точки доступа на каких этажах, названия SSID. Сейчас по ROLES.md это зона Лены, но **это только предложение, не согласовано**. Спросить можно у George или того, кого он назначит.
- Пароли Wi-Fi этажей для ESP32. Прошиваются в плату, **в репо не коммитим**.
- Админ-доступ к роутеру, если используем cron на роутере.
- Аккаунт Healthchecks.io на info@ (завести может George; бот сам аккаунты не создаёт) + **read-only API key** в Script Properties.
- `ADMIN_CHAT_ID` (PLACE Team) уже известен bridge. `GEORGE_CHAT_ID`: George один раз жмёт `/start` у @PlaceLeadBot.
- OK George на `NETMON_MODE=live` и на сообщения в PLACE Team днём.
- Кто в здании прошивает и вешает платы (техник Som?).

## 5. Шаги запуска (после OK)
1. George заводит Healthchecks.io (или разрешает боту подготовить инструкцию).
2. Создаём checks из §3, прошиваем ESP32 с UUID, ставим на этажи.
3. `netmon.gs` в режиме `dry` 2–3 дня: сверяем логи с реальными отключениями.
4. OK George → `NETMON_MODE=live`.
5. Из чек-листов открытия и обходов убираем ручной Wi-Fi (O3, R5).
