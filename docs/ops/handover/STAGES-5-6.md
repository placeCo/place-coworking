## Этап 5: табель (`stage5-timesheet.gs`)

Сейчас так: бухгалтер Sirikanya (hotmail, в копии Somsak) каждый месяц получает табель. По словам Aiz, период 21–20 (это ещё надо подтвердить), а в плане записано «25-е». В листе Schedule 26 (по вкладке на месяц: `Position | Name | 1..31 | Total Hrs.`) графа Total Hrs. в Sep часто пустая.

Что делает шаблон:
- **Период (Aiz Q5, 30.09): календарный месяц, с 1-го по последний день. Табель уходит бухгалтеру 28-го. Отпуск после 28-го удерживается в следующем месяце.** Запуск 28-го берёт текущий месяц:
  - таблица считается по 1–28;
  - дни 29–конец (ещё не отработаны) идут отдельным блоком «After cutoff → next month adjustments»: плановые смены и отпуска;
  - дни 29–конец прошлого месяца идут блоком «Adjustments from previous month»: отпуска, взятые после прошлой отсечки.
  - Настройки: `PERIOD_MODE=month` (по умолчанию), `CUTOFF_DAY=28`. Старая схема 21–20 доступна как `PERIOD_MODE=custom` + `PERIOD_START_DAY/END_DAY`. Точные даты задаются через `PERIOD_FROM/TO`.
  - Приветствие по умолчанию: «Dear Khun Pat,» (новый бухгалтер).
- Понимает смены вида `8:00-17:00`, `8.00 – 17.00`, `8-17`, ночные `23:00-8:00`, а также ячейки с числом часов. Отдельно считает Annual / Sick / Leave without money / Doctor. Всё, что не распознал, выносит в колонку «Unrecognised» для ручной проверки.
- Строку с номерами дней находит сам, колонки настраиваются в Script Properties. Перерыв можно вычитать через `BREAK_HOURS`, по умолчанию 0.
- `dryRun()` только пишет в лог. `createTimesheetDraft()` создаёт **черновик** Gmail (таблица + CSV) и только при `DRAFT_ENABLED=true`. Функции отправки в скрипте нет.
- Адреса бухгалтера в репо не храним, только в Script Properties (`ACCOUNTANT_TO/CC`). Зарплату, SSO и банковские данные скрипт **не** считает, он выдаёт часы и дни неоплачиваемого отпуска. Сам расчёт по правилам из `kb/ops/payroll-rules.md` делает бухгалтер.
