# I-007: камеры Xiaomi в боте (план, 11.10.2026)

George 11.10 19:09: в коворкинге поставим мини-ПК. Делаем go2rtc → снимок/клип в боте с автоудалением, потом Frigate.

## Исходные
- 20 камер Xiaomi Home (облако), модели C200, C300, CW300 (Саша, 11.10).
- go2rtc (1.9.13+) входит в облако Xiaomi, но видео берёт только из локальной сети: значит, сервер должен стоять внутри сети коворкинга.
- Поддерживаются не все модели. C200/C300/CW300 проверяем на первом шаге (протокол cs2 работает хорошо, tutk плохо).

## Железо (мини-ПК, 24/7)
- Под go2rtc + Frigate на 20 камер: мини-ПК на Intel N100 (или новее), 16 ГБ RAM, SSD от 512 ГБ (для записей Frigate лучше отдельный 1–2 ТБ), проводной LAN. Raspberry Pi на 20 камер с Frigate слабоват.
- Ubuntu Server 24.04, ИБП/автостарт после отключения света (в BIOS: "Power on after AC loss").
- Удалённый доступ для Ops: Tailscale (бесплатно), Саша ставит и даёт доступ; никаких открытых портов наружу.

## Шаги
1. Саша: ставит мини-ПК в сеть, Ubuntu, Tailscale. Ops: Docker, go2rtc.
2. Вход go2rtc в аккаунт Xiaomi (код придёт на почту/телефон владельца аккаунта: один раз). Проверка всех 20 камер, список рабочих/нерабочих.
3. Отдельный бот для камер (новый токен BotFather), скрипт на мини-ПК: команда «камеры» → кнопки по камерам → снимок (frame.jpeg) или клип 15 с (stream.mp4?duration=15) → удаление сообщения через 30 с. Доступ: George, Лена, Саша, Никита; только личка. ИИ не используется.
4. Потом Frigate на том же ПК: детекция людей/движения, архив, уведомления (объём и правила согласовать с George отдельно).

## Открыто
- Покупка мини-ПК (George), кто ставит (Саша).
- Аккаунт Xiaomi: на чей телефон/почту придёт код входа.
